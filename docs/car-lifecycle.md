# أرشفة السيارات وإدارة الارتباطات

## تفعيل قاعدة البيانات

شغّل الملف `supabase/migrations/20261027_car_lifecycle.sql` مرة واحدة في SQL Editor
لمشروع Supabase `olpjfipferziqtzrbbbt`. الملف يثبت الدوال والحماية فقط، ولا ينفذ
أي إلغاء أو حذف أو أرشفة على البيانات الموجودة، ولا يغير حسابات الموظفين.
يمكن إعادة تشغيله بأمان. بعده يمكن التحقق دون تغيير البيانات:

```powershell
node scripts/check-car-lifecycle.mjs
```

## مسار الاستخدام

1. السيارات ← إدارة. تظهر أسماء العملاء وأرقام الحجوزات ومواعيدها وحالاتها.
2. الطلب غير المؤكد والحجز المؤكد قبل التسليم: إلغاء مع سبب محفوظ.
3. العقد الجاري: الاستلام والإغلاق من نموذج الاستلام الموجود، وليس الإلغاء.
4. بعد إغلاق أو إلغاء كل الحجوزات المفتوحة: أرشفة السيارة.
5. الأرشيف: تفاصيل وسجل كامل، أو إعادة بحالة صيانة للفحص قبل الإتاحة.
6. الحذف النهائي متاح فقط عند عدم وجود أي حجز مرتبط، حتى لو كان ملغى.

السيارة المؤرشفة مخفية عن كتالوج الزبائن والحجوزات الجديدة والتنبيهات التشغيلية.
تبقى العقود والفواتير والعلاقات مع المالك محفوظة، ولا تعني الأرشفة إلغاء اتفاق
المالك أو تعديل حساباته. حالة الأرشفة تدخل في النسخ الاحتياطية التشغيلية المعتادة.

## الأموال والسجلات

الإلغاء لا يحذف الحجز أو الفاتورة، ولا ينفذ استردادًا نقديًا. يوقف النظام إلغاء حجز
له فاتورة مدفوعة بقيمة موجبة أو تأمين محتجز/مسترد جزئيًا حتى مراجعة التسوية
المالية. مسار التسويات المالية مستقل ويحتاج إجراء محاسبيًا معتمدًا؛ لا نغيّر
الفواتير القديمة أو ندعي صرف مبلغ للعميل تلقائيًا.

التغيير في الحالة إلى صيانة لا يلغي حجزًا أو ينهي عهدة العميل. العقود المتأخرة
تظل مانعة للأرشفة حتى الاستلام والإغلاق. الحالة غير المعروفة تعامل كارتباط
مفتوح يحتاج مراجعة. فحص الحالة يحدث داخل قاعدة البيانات وليس اعتمادًا على
القائمة المعروضة في المتصفح. تُقفل صفوف السيارة والحجز عند العملية، وتبقى
العمليات ذرية بما فيها سجل نشاط الموظف. صلاحية التنفيذ للخادم فقط بعد التحقق
من المدير النشط، وبقية الموظفين لا يحصلون على صلاحيات جديدة.
